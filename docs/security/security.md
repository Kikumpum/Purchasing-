# Keamanan

- Supabase Auth dengan invite, password recovery dan session refresh server-side. Validasi identitas menggunakan metode resmi SDK saat Phase 3. Profile aktif dan assignment dibaca dari database. Role di payload atau user metadata editable tidak menjadi otoritas. Konfigurasi redirect allowlist dan audit lifecycle akun. Catat autentikasi dari log Auth yang tepercaya, serta event aplikasi dari sesi terverifikasi.
- Terapkan row-level security pada tabel aplikasi yang terekspos dan gunakan schema privat untuk helper serta data yang hanya dipakai fungsi tepercaya. Grants minimal. Tabel mutasi workflow tidak memberi write grant pada authenticated. Identitas untuk query reguler berasal dari sesi pengguna.
- Gunakan security invoker bila grants dan RLS memadai. RPC yang butuh privilege khusus memakai security definer dengan owner khusus dan hak minimum, search_path tetap serta nama schema-qualified. Cabut execute default dari PUBLIC/anon dan grant hanya ke role teknis yang diperlukan. RPC memeriksa auth.uid, role, scope, aktor dan state sebelum menulis. Jangan mengandalkan RLS yang mungkin dilewati owner fungsi.
- Read model yang memakai view harus menjalankan role pengguna dengan security invoker jika tersedia. Untuk proyeksi warehouse, gunakan kolom yang diizinkan melalui RPC baca yang memeriksa scope atau model proyeksi terpisah yang di-RLS. Lindungi tabel harga dan metadata pribadi dengan grants yang sesuai. Uji view, join, filter dan export sebagai pengguna biasa.
- Validasi struktur dengan Zod pada server dan ulangi invariants bisnis di DB. Verifikasi origin mutasi berbasis cookie, batasi abuse login/recovery, dan batasi ukuran input/aliran ekspor. Jangan gunakan cache lintas sesi untuk respons privat.
- Audit append-only untuk mutasi domain. Simpan aktor, waktu, alasan, daftar field berubah dan correlation ID. Allowlist metadata. Akses baca audit dipisah dari role biasa. Dokumentasikan retensi serta ekspor audit sebelum rilis.
- Penyimpanan dokumen opsional memakai private bucket. Cek izin dokumen induk sebelum upload atau penerbitan URL sementara. Validasi MIME dan isi, ukuran, UUID object key dan status keterkaitan. Bersihkan upload yatim dengan prosedur operasional. Terapkan akses per role untuk bukti sensitif.
- Simpan credential Supabase hanya di env yang sesuai. Kunci publishable untuk client. Kunci privileged hanya untuk operasi Auth admin yang sah bila dibutuhkan; setiap operasi memeriksa otorisasi dan mencatat hasil. Pisahkan runtime aplikasi dari kredensial migrasi.

Rujukan untuk grants, policies dan default akses fungsi. [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) · [Supabase database functions](https://supabase.com/docs/guides/database/functions).

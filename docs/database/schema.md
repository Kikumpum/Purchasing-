# Rancangan basis data

Gunakan UUID PK untuk dokumen/entitas, FK dengan RESTRICT untuk histori, dan constraint NOT NULL untuk data yang wajib. Nama umum, kode, tanggal, aktor serta state menggunakan tipe yang sesuai. Tetapkan domain kuantitas numeric(18,6), harga satuan numeric(19,6) dan total numeric(19,4) sebagai usulan awal. Terapkan check rentang dan tolak skala input yang melebihi kontrak sebelum konversi. Simpan kode mata uang, scale mata uang, dan aturan pembulatan snapshot. created_at/updated_at timestamptz serta created_by/updated_by digunakan pada data yang dapat berubah. Histori append-only memakai waktu dan aktor event.

| Kelompok | Kunci, relasi dan constraint penting |
|---|---|
| Organisasi | profiles.id FK auth.users, role satu dari empat nilai, status aktif, FK department. departments.code unik. manager_department_access dan user_warehouse_access unik per pasangan aktor dan scope. Akses transfer, receive, issue dan count bisa diberikan per gudang. |
| Master | products.sku unik, FK kategori dan UOM dasar, status aktif. Kode kategori/UOM/gudang/vendor unik per jenis. vendor_contacts dan vendor_addresses FK vendor. inventory_thresholds unik per gudang/produk. |
| PR | Nomor PR unik dari sequence, requester/department snapshot, need_by, business purpose, status, version, approval_round, approver_id. PR item unik per dokumen dan nomor baris, qty > 0, FK produk dan snapshot UOM. Approval unik per PR/round. Histori menyimpan from/to, version, actor dan komentar. |
| Pemenuhan | fulfillment_allocations FK PR item dan gudang, jenis internal/external, qty terkomit, qty resolved, qty issued. Satu baris PO per alokasi eksternal. Reservasi FK alokasi dan saldo dengan qty terbuka dan status. Ekspansi qty terlarang setelah ada PO atau posting. Aggregate lintas alokasi divalidasi di bawah lock baris PR item. |
| Quotation dan PO | Quotation terkait PR, vendor, mata uang dan validity; item FK PR item. Versi baru untuk perubahan sesudah penggunaan. PO FK PR, vendor, gudang tujuan, nomor unik, lifecycle, ETA, snapshot vendor, biaya, pembulatan dan total. Setiap baris mereferensikan alokasi dan quotation item yang cocok dengan PR, produk dan vendor. |
| Receipt dan issue | Receipt FK PO dengan receipt number unik dalam sistem, reference vendor opsional, tanggal dan aktor. Baris receipt berisi qty diterima layak dan ditolak, key per dokumen/baris PO. Issue FK PR/gudang, penerima, tanggal dan aktor. Baris issue FK reservasi, qty positif, key per dokumen/reservasi. |
| Transfer | FK asal/tujuan berbeda, status, nomor dokumen unik. Satu baris per produk. Transfer receipt memiliki baris dengan jumlah diterima per baris transfer. Qty kumulatif terkunci. |
| Opname/adjustment | Opname per gudang, baris unik per produk, baseline qty dan stock_version, count qty, count_revision, alasan. Adjustment unik per baris dan count_revision, menyimpan delta, pengaju, penyetuju, state dan referensi posting. Partial unique index membatasi satu posting efektif per baris. |
| Saldo dan ledger | inventory_balances PK (warehouse_id, product_id), physical_qty >= reserved_qty >= 0, version bertambah setiap mutasi saldo/reservasi, stock_version bertambah pada perubahan fisik. inventory_transactions berisi aktor, jenis dan real FK sumber sesuai tipe. stock_movements memiliki txn FK, qty delta != 0, FK produk dan tepat satu lokasi berupa gudang atau transfer item. |
| Sistem | notifications FK recipient, event dan read_at, unique event/recipient. audit_logs append-only dengan metadata allowlist. operation_keys unik (actor_id, operation, idempotency_key), menyimpan hash payload normal dan hasil. Attachment metadata privat mengikuti scope dokumen bila bukti diaktifkan. |

FK komposit atau validasi RPC terkunci menjaga kecocokan dokumen induk, produk dan gudang lintas baris. Inventory transaction mempunyai FK bertipe per receipt, issue, pengiriman transfer, penerimaan transfer, adjustment, dokumen saldo pembukaan, atau dokumen kompensasi yang mereferensikan transaksi asal. Aturan tepat satu sumber memakai check dan partial unique index per source ID. Pembalikan parsial bila diaktifkan memakai batas kumulatif di bawah lock transaksi asal. Status history terpisah per jenis dokumen memakai FK asli. Audit gabungan menyimpan ID entitas dan snapshot terpilih.

## Kontrak penulisan

1. Verifikasi aktor aktif, role, scope dan command. Claim operation key pada transaksi yang sama. Replay payload sama membaca hasil setelah otorisasi ulang. Payload berbeda dengan key sama menghasilkan conflict.
2. Ambil row lock atas root PR yang relevan, baris PR berurutan, dokumen sumber dan barisnya, lalu saldo (urut warehouse_id, product_id). Untuk flow tanpa PR, mulai dari dokumen sumber. Definisikan urutan lintas tipe dan gunakan pada setiap command dan reversal. Inisialisasi baris saldo nol dalam urutan yang sama dengan UPSERT sebelum mengambil lock. Perubahan assignment yang harus menyerialisasi operasi menggunakan guard bersama yang didefinisikan pada Phase 3.
3. Baca state dan kuantitas setelah lock. Validasi jumlah kumulatif, snapshot/version dan produk/gudang. Perintah stok memperbarui balance, ledger, reservasi, dokumen, audit dan event dalam satu transaksi. Perintah reservasi hanya mengubah reserved_qty serta histori alokasi. Version fisik berbeda dari version reservasi.
4. Rollback seluruh perubahan saat gagal. Untuk deadlock atau konflik serialisasi, lakukan retry terbatas dengan operation key yang sama. Konflik domain meminta pengguna memuat ulang data.
5. Rekonsiliasi fisik dengan SUM delta ledger per gudang/produk, reserved dengan total saldo reservasi aktif, dan transit dengan delta akun transit per baris transfer. Semua opening balance diposting melalui transaksi pembukaan resmi dengan bukti, aktor dan referensi unik.

## Indeks dan query

Indeks FK hot path, PR (requester_id, created_at, id), PR (approver_id, status, submitted_at), PR (department_id, status, created_at), PO (warehouse_id, status, eta), PO (vendor_id, order_date), saldo (product_id, warehouse_id), ledger (warehouse_id, product_id, occurred_at, id), receipts (po_id, received_at), dan notification (recipient_id, created_at) dengan partial index unread bila terukur. PK dan indeks unik mendukung replay dan referensi. Ukur query dengan EXPLAIN pada volume representatif. [PostgreSQL explicit locking](https://www.postgresql.org/docs/current/explicit-locking.html).
